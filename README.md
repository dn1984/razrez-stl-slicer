# Разрез / Razrez

[Русская документация](#разрез--нарезка-stl-на-части-для-3d-печати) · [English](#english)

## English

Razrez is an offline-first STL slicer for splitting closed 3D-printable models into separate parts with practical assembly joints. It supports flat, domed, and dished cuts; contour steps; parallel pin-and-hole joints; tongue-and-groove joints; a configurable second cutting plane; exploded inspection; table layout; and STL/project export.

The app runs entirely in the browser with no runtime network requests. Geometry is computed locally with Manifold 3D WebAssembly and rendered with Three.js. Open `dist/index.html` directly for the standalone offline build, or use the Vite development server.

### Quick start

```powershell
npm install
npm run dev
```

Build and verify:

```powershell
npm run build
npm test
npm run test:e2e
```

See the Russian documentation below for the complete feature description.

---

Настольная программа: открывает STL, режет модель плоскостью с автоматическими
замками (ступенька, штифты с отверстиями, шип-паз), позволяет сделать срез
выпуклым или вогнутым, раздвинуть части и сохранить каждую отдельным STL.

Ничего не устанавливает, не требует интернета, не отправляет модели наружу —
вся геометрия считается на вашем компьютере.

## Как запустить

**Готовое приложение — один файл:**

```
dist/index.html
```

Двойной щелчок — откроется в браузере. Всё внутри: интерфейс, геометрическое
ядро (WebAssembly), шрифты. Интернет не нужен, работает и с флешки.

**Режим разработки** (нужен Node.js и уже установленные `node_modules`):

```powershell
npm run dev      # http://localhost:5199
npm run build    # пересобрать dist/index.html
```

Установка зависимостей (`npm install`) требует сети — она уже выполнена,
`node_modules` на месте. Пересборка работает офлайн.

## Что умеет

### Рез плоскостью
- Ось X / Y / Z, положение ползунком, наклон до ±90°.
- Контур сечения показывается сразу — оранжевой линией на модели.
- **Ограниченная область реза** — плоскость режет не всю деталь насквозь, а
  только прямоугольное окно в ней: задаются ширина, высота и сдвиг окна.
  Всё, что за окном, остаётся целым: можно отпилить крыло самолёта, не задев
  хвост. В сцене плоскость превращается в это окно, размер и положение видно
  до нажатия «Разрезать». Замки (штифты, ступенька, шип) ставятся только
  внутри окна.

  Под окном показано, сколько сечения в него попадает и где проходят его
  границы в координатах модели. Если окно накрывает больше 70 % сечения,
  появляется предупреждение: значит рез заденет не только нужный участок.
  Без окна рез идёт по всей детали — это обычный рез плоскостью.

  В сцене окно рисуется **объёмной рамкой** — призмой вдоль нормали, поэтому
  видно, какие части детали попадают под рез, а какие остаются за его
  пределами. Боковые стенки призмы становятся поверхностями среза только там,
  где окно проходит через материал: если окно целиком содержит нужный кусок
  (например законцовку крыла), срез получается чистым, без ступеньки.
- **Второй рез** — отдельная плоскость: своя ось, положение, наклон,
  **своя ограниченная область** (ширина, высота, сдвиги) и переключатель
  «держать параллельно первому». Контур второго реза рисуется на модели
  бирюзовым пунктиром, плоскость — бирюзовой рамкой; видно оба реза сразу,
  ещё до нажатия «Разрезать». Если первый рез ограничен окном, второй
  наследует его размер — иначе он молча режет деталь насквозь. Подсказка
  предупредит, если плоскости совпали, оказались параллельны или один из
  резов остался без ограничения. В проверках видно, сколько разрезов сделал
  каждый рез.

### Форма среза
- **Плоский** — ровные поверхности, проще всего печатать.
- **Выпуклый** (купол) — срез выгибается наружу, стык сам садится на место.
- **Вогнутый** (тарелка) — с ложем, край детали защищён от сколов.
- Высота скругления задаётся; изгиб — плавный или сферический.

### Замки на срезе
- **Ступенька по контуру** — выступающий поясок по всему сечению. Самый
  прочный вариант под склейку, детали сами центрируются.
- **Штифты с отверстиями** — расстановка «самая дальняя точка»: каждый
  следующий штифт ставится максимально далеко от уже поставленных, поэтому
  заказанное количество действительно влезает даже на маленьком сечении
  (20 × 20 мм — четыре штифта ⌀4 мм). Конусность для лёгкой посадки,
  настраиваемый зазор. `Shift` + клик по срезу добавляет штифт вручную.
  Если штифты физически не помещаются, вы увидите, сколько влезло и почему.
- **Шип-паз** — широкий выступ с ответным пазом вдоль самой длинной хорды.

Все замки строятся в системе координат среза, поэтому следуют его форме
(купол, тарелка) и не вылезают за поверхность раздела.

### Части
- Список частей с объёмами, выбор мышью.
- **Склейка частей обратно.** Отметьте галочками части, которые должны быть
  одним телом, и нажмите «Склеить отмеченные». Шов между ними исчезает, а
  граница с остальными остаётся. Это правильный способ отрезать только крыло:
  режьте плоскостью насквозь, а потом склейте обратно всё лишнее — стенок окна
  при этом нет вообще.
- Ползунок «Разнести» — раздвигает части вдоль нормали среза для проверки.
- «Разложить на столе» — раскладывает части рядом на плоскости печати.
- Перемещение и поворот части мышью (`G` / `R`), `F` — показать всё.
- Сохранение: в выбранную папку одним действием (File System Access API) или
  по файлу через загрузки браузера. Проект (`.razrez.json`) хранит настройки
  реза, чтобы вернуться к ним позже.

## Что проверяется автоматически

После каждого реза приложение само считает и показывает:

- **Части не пересекаются.** Пересечение меряется булевой операцией; больше
  шума округления — значит, детали не собрать.
- **Материал в пределах замков.** Объём может измениться (выступы добавляют,
  выемки с зазором убирают чуть больше), но не больше, чем заложено замками.
  Выход за пределы означал бы потерянный или лишний материал.

Обе проверки — не «на глаз»: числа приходят из геометрического ядра.

---

## Толщина материала учитывается

Приложение зондирует деталь лучами и не даёт замку пробить её насквозь:

- ступенька и шип автоматически укорачиваются под толщину детали;
- штифт ставится только там, где хватает материала с обеих сторон
  (толщина не меньше диаметра плюс запас), иначе он пропускается с пояснением;
- на крутом склоне среза штифт укорачивается, чтобы не выйти через боковую
  стенку.

Толщина считается полным сканированием линии, а не лучом от идеальной
поверхности: срез фасетирован, и реальная грань лежит на десятые доли
миллиметра выше гладкой кривой профиля.

Если замок не поместился, вы увидите причину с числами, а не молчаливую дырку
в детали.

---

## Почему штифты параллельны

Все штифты идут строго по нормали плоскости среза, а не по местной нормали
поверхности. На куполе или тарелке местные нормали расходятся веером — такие
штифты физически невозможно вставить, детали надо было бы надвигать сбоку.
Параллельные штифты собираются движением по нормали, как и положено.

## Устройство

```
src/
  geometry/     ядро без интерфейса — тестируется отдельно
    stl.ts        разбор и запись STL (бинарный и ASCII)
    manifold.ts   обёртка над manifold-3d: сварка вершин, сборка тела
    profile.ts    профиль среза и режущие тела вращения
    joints.ts     ступенька, шип-паз, штифты, зондирование толщины
    cut.ts        оркестрация реза, проверки, статистика
    math.ts       векторы, базисы плоскостей, тесты попадания точки
  worker/       воркер: вся тяжёлая математика вне главного потока
  viewer/       three.js: сцена, плоскости реза, части, маркеры штифтов
  ui/           стили
  app/state.ts  состояние и расчёт параметров реза
  io/files.ts   сохранение STL и проекта
  main.ts       связка интерфейса, сцены и воркера
tests/
  unit/         геометрия: объёмы, замки, толщина, сборка
  e2e/          Chromium: реальный прогон интерфейса и проверка STL в Node
  check-encoding.mjs   проверка, что исходники не испорчены кодировкой
```

Технологии: TypeScript, Vite, three.js, manifold-3d (WebAssembly),
vite-plugin-singlefile.

## Тесты

```powershell
npm test                    # 39 юнит-тестов геометрии
npm run test:e2e            # 49 проверок в headless Chromium
node tests/check-encoding.mjs   # проверка кодировки исходников
```

Юнит-тесты проверяют физику, а не флаги: сечение детали на нужной глубине,
совпадение осей штифтов с нормалью, отсутствие материала за габаритом,
сборку деталей сдвигом, замкнутость сохранённых STL, заказанное число
штифтов на маленьком сечении, отсутствие «уехавших углов» при смещённом
втором резе.

E2E открывает собранный `dist/index.html` по `file://`, проверяет кнопку
«Открыть STL» (выбор файла), режет три модели (куб, кронштейн с отверстием,
тор), скачивает STL и в Node проверяет, что каждая часть — замкнутое тело и
что сумма объёмов совпадает с приложением.

Отдельные ручные прогоны: `node tests/e2e/visual.mjs` (снимки замков) и
`node tests/e2e/chep.mjs` (проверка на калибровочном кубике CHEP).

E2E использует уже установленный Chromium из `%LOCALAPPDATA%\ms-playwright`
или системный Chrome/Edge — скачивать браузер не нужно.

## Ограничения

- Входной формат — STL (бинарный и ASCII). 3MF и OBJ пока не поддерживаются.
- Незамкнутую сетку приложение не режет: показывает код ошибки и совет, чем
  починить модель.
- Замки рассчитаны на FDM; зазор по умолчанию 0,2 мм (для SLA ставьте 0,05).
- Модель в дюймах нужно увеличить на 2540 % — приложение предупредит, если
  габарит меньше 1 мм.
- Лончер для Windows (своё окно, ассоциация `.stl`) не сделан: приложение
  открывается как файл в браузере.
